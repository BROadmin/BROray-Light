# Проверки BROray-Light 3.5.10

## Сборки

Сборки A и B скомпилированы из двух извлечений Git-коммита `005a0543c88a818e278bd4c62db16796bdbfe1f9`. Для кросс-сборок на Windows использованы Go 1.24.13 и разные кэши. Инструмент `tools/light-release` проверяет Linux ABI, класс и порядок байт ELF, отсутствие динамической загрузки, `CGO_ENABLED=0` и целевые параметры Go. Покомпонентное сравнение GPT-6.2 Sol подтвердило равенство четырёх архивов, четырёх бинарников, SHA-256 и таблицы размеров. Воспроизводимые архивы включают лицензии Light, Go и vendored-зависимостей.

Поставляемый архив исходников закреплён на `43f1ceeed169ae235db24fd8c8ea3aba9fff65df`. В нём исправлена Xray-фикстура и обновлены инструкции. Контрольная сборка из этого дерева воспроизвела все SHA-256 и размеры A/B.

Донор требует Go 1.24. Выбран патч-релиз 1.24.13 той же линии. При выборе учтены Linux 3.2–3.10 в целевых поколениях Entware. Совместимость с каждой конкретной прошивкой требует аппаратной проверки. [Примечания Go 1.24](https://go.dev/doc/go1.24#linux)

## Проверки на хосте

Стенд — изолированный Alpine Linux/QEMU x86-64, ядро 6.12.94, Go 1.24.13, GCC 14.2.0, Node 22.23.5. Виртуальная машина использует loopback. WSL-дистрибутив в среде выполнения отсутствует.

- `go test -count=1 ./...`, `go test -race -count=1 ./...` и `go vet ./...` завершились с кодом 0.
- `node --check web/light/assets/light.js` и `sh -n internal/lightinstall/init.sh` завершились с кодом 0.
- Host smoke запустил статический amd64 из проверенного исходника. Проверены версия, три HTTP-страницы, встроенные JS/CSS, закрытый API, локальный control socket и отказ при конфликте с полным BROray.
- Host smoke с официальным Xray `26.11.9` связал Light с локальным VLESS-сервером и HTTP-ответом через SOCKS. До появления upstream команда готовности возвращала отказ, активный ID оставался на диске. После появления upstream путь восстановился и readiness прошла. SIGKILL демона закрыл принадлежащий ему SOCKS, независимый Xray остался доступен.
- Go-регрессии проверяют подтверждённое удаление активного сервера, сохранение ID при ротации, дедупликацию, порог и интервал резервирования, паузу при подтверждённом сбое WAN, отказ при чужом интерфейсе и маршрутах, подпись и содержимое обновления, откат неподтверждённого бинарника, переход при перезагрузке и сохранение метаданных очистки.

У донорского теста таймаута NDW была поднята длительность тестового ожидания для эмулированного хоста. Проверка единственного POST сохранена. В первом прогоне ВМ объём RAM-диска оказался недостаточным. ВМ повторного прогона получила 6 ГиБ. Первоначальная Xray-фикстура дошла до VLESS, но упёрлась в встроенную политику Xray для частных адресов. Коммит `43f1ceeed169ae235db24fd8c8ea3aba9fff65df` разрешил только один loopback HTTP endpoint в конфигурации фикстуры. Код приложения в этой правке не менялся. [Настройки Freedom Xray](https://github.com/XTLS/Xray-docs-next/blob/main/docs/en/config/outbounds/freedom.md)

Логи проверенных этапов находятся в папке `evidence`: `build-a.log`, `build-b.log`, `source-roundtrip.log`, `linux-checks.log` и `linux-smoke.log`.

## Границы проверки

Проверки Keenetic используют native HTTP/NDMC-фикстуры. Физический роутер, целевые Linux 3.2–3.10 и живой опубликованный канал Light требуют отдельной приёмки. Текущие архивы локальные. Обновитель проверен на подписанных фикстурах. Импорт из shell Light выполняется вручную по инструкции. Официальные MIPS/MIPSEL-пакеты Xray собраны с `hardfloat`, в отличие от приложения Light. Размеры и матрица ядра приведены отдельно в `XRAY-SIZES.tsv`.
